# Шаг 07 — Видео: обычные видео, качество, озвучка, субтитры; Фильмы: поиск, жанры, годы, загрузки (0.2.4)

**Запрос.** Вкладка «Видео»: не только эфиры, а обычные видео; выбор качества (хотя бы 720p — «а то мыло»), перевод голоса (озвучка) и субтитры, как на YouTube — чтобы смотреть сериалы и фильмы. Вкладка «Фильмы»: поиск, добавление с ПК, возможность «гуглить» и скачивать фильмы разных годов, советские и зарубежные, разных жанров.

## Что выяснено перед работой
Проверка зеркала Invidious на популярном видео:
- в HLS-плейлисте YouTube есть качества **144p–1080p в H.264** (их тянет iPad mini 1) и выше в VP9 (A5 не умеет);
- **44 дорожки озвучки**, в том числе **«Русский — dubbed»** (официальный дубляж YouTube);
- **42 дорожки субтитров** прямо в потоке, в том числе русские;
- автоперевод субтитров (`tlang=ru`) зеркало не делает — показываются языки, которые есть у видео.

Почему было «мыло»: в лёгком режиме плеер начинал с самого низкого качества и ограничивал 480p, а встроенный плеер iOS сам выбирает качество по скорости сети.

## 1. Меню ⚙ в плеере — `web/js/player.js`
Для видео YouTube в верхней панели плеера — кнопка ⚙:
- **Качество:** Авто / 1080p / 720p / 480p / 360p (только реально доступные у видео; по умолчанию **720p**);
- **Озвучка:** оригинал или перевод на другой язык (русский — первым; по умолчанию русский, если есть);
- **Субтитры:** выключены или язык (русский — первым).

Выбор запоминается (`settings.ytQuality`, `ytAudio`, `ytSubs`) и применяется ко всем следующим видео. При смене качества видео продолжается с того же места (`state.resumeAt`).

Как применяется выбор:
| Где | Как |
|---|---|
| iOS-приложение | видео идёт через локальный сервер приложения `http://127.0.0.1:<порт>/hls?...` (см. п. 2) + `video.audioTracks`/`textTracks` |
| ПК, Android, ТВ (hls.js) | `hls.currentLevel` (качество), `hls.audioTrack`, `hls.subtitleTrack` — переключаются на лету (`applyHlsJs`) |
| Safari без приложения | `video.audioTracks` / `video.textTracks` (`applyMediaTracks`) |

Список качеств и дорожек берётся из самого плейлиста: `TV.yt.hlsInfo(url)` в `services.js`.

## 2. Локальный сервер в iOS-приложении — `ios/src/main.m` → `TVLocalServer`
Встроенный HLS-плеер iOS не даёт из JavaScript выбрать качество и озвучку. Поэтому приложение поднимает сервер на `127.0.0.1` (порт 18080–18099, передаётся странице как `TV_NATIVE.port`):
- **`/hls?u=…&h=720&a=ru&s=ru`** — скачивает исходный плейлист и отдаёт копию (`TVRewriteMaster`): только H.264, только выбранное качество (у «Авто» — всё до 1080p), выбранные озвучка и субтитры помечены `DEFAULT=YES`, ссылки абсолютные. Видео по-прежнему идёт с зеркала — через сервер проходит только маленький текстовый плейлист.
- **`/file/<имя>`** — раздаёт скачанные фильмы с поддержкой `Range` (перемотка).
- `SO_NOSIGPIPE` — обрыв соединения плеером не роняет приложение; после сна iOS сокет поднимается заново.

## 3. Вкладка «Видео» — `web/js/app.js` (`S.yt`, `runYv`)
- **Строка поиска** + фильтры: тип (▶️ Видео / 🔴 Прямые эфиры), длительность (до 4 мин / 4–20 мин / **больше 20 мин — фильмы и сериалы**), сортировка (подходящие / новые / популярные); «Ещё результаты» — следующая страница.
- **Рубрики обычных видео** (`TV.yt.shelves`): В тренде, Фильмы целиком, Сериалы, Мультфильмы, Музыка и клипы, Юмор, Наука и познавательное, Новости, Спорт, Игры, Кулинария, Путешествия; эфиры — последней полкой.
- Параметры поиска Invidious: `duration`, `sort_by` (`TV.yt.search`).

## 4. Вкладка «Фильмы» — `web/js/films.js` (новый) и `S.movies`
- **Поиск фильма** (название, актёр, режиссёр) + фильтры: **жанр** (комедия, драма, боевик, фантастика, ужасы, детектив, мелодрама, военный, приключения, вестерн, мультфильм, документальный), **годы** (2020-е … до 1950), **страна** (советские и российские / зарубежные).
- Ищет сразу в двух источниках (`TV.films.search`): YouTube — только ролики от 20 минут (запрос дополняется жанром, годами, происхождением); Архив кино — по полям `subject` и `year`. Для «советских» архив не используется (см. LEGAL).
- **🔎 Искать в Google** — открывает поиск Google в Safari.
- **📥 Загрузки** (`TV.dl`, `S.downloads`): кнопка ⬇ в плеере скачивает на iPad фильм Архива кино, свою ссылку на mp4 или файл с ПК; прогресс, удаление, просмотр без интернета. Нативная часть — `TVDownloads` (NSURLSession, файлы в `Documents/BridgeTV-downloads`, исключены из резервной копии). Незаконченные загрузки после перезапуска помечаются «прервано».
- **💻 С компьютера** и **🔗 По ссылке** — как раньше, плюс файл с ПК можно скачать на iPad.
- Видео YouTube не скачиваются — это запрещают правила YouTube.

## Субтитры — как сделаны и почему так
Первая версия брала субтитры из HLS-потока. При проверке выяснилось: через зеркало плейлисты субтитров потока **не загружаются** (`subtitleTrackLoadError`). hls.js считал это фатальной ошибкой и **ронял всё видео** («Связь прервалась»).

Теперь:
1. Субтитры потока отключены: `enableWebVTT: false` в hls.js, а локальный сервер iOS вырезает группу `SUBTITLES` из плейлиста. Ошибка субтитров никогда не останавливает видео.
2. Субтитры берутся из API зеркала (`captions` в `/api/v1/videos/ID` — файлы WebVTT): `TV.yt.resolve` возвращает их списком, плеер (`setSubtitles`) скачивает выбранный файл через мост (без CORS) и подключает дорожкой `<track>` через blob-адрес. Работает и в hls.js, и во встроенном плеере iOS.
3. У YouTube соседние реплики накладываются по времени, и строки на экране дублировались. `tidyVtt()` обрезает конец каждой реплики к началу следующей (проверено: 0 наложений из 1056).
4. Смена субтитров — без перезагрузки видео.

Проверено в браузере на видео с официальным дубляжом: **720p, русская озвучка, русские субтитры** одновременно; переключение на 1080p продолжает с того же места.

## Ошибка сборки, пойманная CI
Первая сборка 0.2.4 упала на компоновке armv7: `(unsigned long long)(дата * 1000)` требует `___fixunsdfdi`, которого нет в SDK iOS 9. Исправлено форматом `%.0f`; правило добавлено в [IOS.md](../IOS.md).
