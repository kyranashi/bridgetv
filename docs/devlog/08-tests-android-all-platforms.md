## 2. Исправленные ошибки
| Ошибка | Причина | Исправление |
|---|---|---|
| **Список ☰ не закрывается** (сообщил пользователь) | панель выезжает справа и перекрывает саму кнопку ☰ | ✕ в шапке списка; закрытие касанием по видео, кнопкой «Назад»/Esc на пульте и после выбора пункта (`P.panelOpen`, `P.closePanels` в `player.js`); то же для меню ⚙; заголовок «Каналы»/«Список» |
| **Рывки при повороте** (сообщил пользователь) | под плеером оставалась вся страница (сотни карточек и картинок) — при повороте пересчитывалась целиком | пока открыт плеер, страница скрыта (`html.playing #app { display:none }`), плеер на отдельном графическом слое; прокрутка возвращается после закрытия; на Android `configChanges` — поворот без перезапуска экрана |
| Поиск латиницей | транслит в индексе «pervy», в запросе «pervyi» | `TV.latinKey()` сводит варианты (i/y/j, kh/h, w/v) с обеих сторон |
| «Продолжить» | плеер получал только список недавних | открывается весь список региона на этом канале |
| «Советские» фильмы | поиск YouTube подмешивает чужие ролики | для «Советские и российские» — только с русским названием |
| Служебные символы в коде | правка скриптом вставила невидимые `\b` в регулярное выражение | исправлено, весь код проверен на управляющие символы |

## 3. Без джейлбрейка и на новых устройствах (iOS)
Почему раньше не открывалось без джейлбрейка: `.ipa` подписан «пустой» подписью — iOS запускает только подписанное Apple ID. Это ограничение Apple, а не приложения: переподписать нужно своим Apple ID (Sideloadly — работает и на iPad mini 1 с iOS 9, AltStore, TrollStore, платный аккаунт). Подробно — [IOS.md](../IOS.md), раздел «Без джейлбрейка».

Для новых iPhone/iPad (чтобы не было «рамки совместимости»):
- `tools/make_launch_images.py` — экраны запуска под iPhone X…16 и iPad Pro/Air/mini (13 картинок, 18 записей `UILaunchImages`);
- `UILaunchScreen` в `ios/res/Info.plist` (iOS 14+);
- `tools/set_sdk_version.py` — в заголовке бинарника SDK 14.0 при минимальной iOS 9.0 (запускается в `ios/build.sh` до подписи). Проверено: оба среза (armv7, arm64) — min 9, sdk 14; `check_ipa.py` — совместимо с iOS 9.

## 4. Android — `android/` (новое)
- WebView-оболочка на Java без сторонних библиотек: `MainActivity` (экран, «Назад», полноэкранное видео, SSL для старых Android) и `Bridge` (мост `window.TVAndroid` с теми же командами, что у iOS).
- Android 4.4+ (minSdk 19) … Android 15 (targetSdk 34); телефоны, планшеты, **Android TV** (баннер, `LEANBACK_LAUNCHER`, пульт).
- Запросы: TLS 1.2 на Android 4.4 и корни Let's Encrypt для Android < 7.1.
- `web/js/core.js`: определение платформы `TV.platform` (ios / android / web), мост для Android.
- Сборка: `.github/workflows/android.yml` (Java 17, Gradle 8.5, AGP 8.2). Первая же сборка прошла: APK 2,6 МБ, подписан, внутри интерфейс, 458 иконок, hls.js, корневые сертификаты.
- Подпись: создан постоянный ключ проекта (`releases/android-signing/`, не в git). Записать его в секреты GitHub автоматически не разрешено правилами безопасности — это делает владелец двумя командами ([ANDROID.md](../ANDROID.md)). До этого CI подписывает отладочным ключом из кэша.

## 5. Остальные форматы — `tools/package.py` (новое)
| Файл | Для чего |
|---|---|
| `BridgeTV-<v>-web.zip` | любой ПК: `start-windows.bat` / `start-mac-linux.sh` запускает сервер и браузер; по Wi‑Fi — на iPad/ТВ |
| `BridgeTV-<v>-tizen.wgt` | Samsung Smart TV (Tizen 2.3+); подписывается сертификатом Samsung в Tizen Studio |
| `BridgeTV-<v>-webos.ipk` | LG Smart TV (webOS), режим разработчика (экспериментально) |
CI: `.github/workflows/packages.yml`. Пульт Samsung: в `nav.js` регистрируются цифры, CH± и медиакнопки (`tizen.tvinputdevice`).
Подробно — [SMART_TV.md](../SMART_TV.md).

## Что не проверено (нет устройств)
- APK на реальном Android, `.wgt` на Samsung, `.ipk` на LG — собраны и разобраны (структура верная), но запуск на устройствах — за пользователем.
- Полноэкранный режим на новых iPhone/iPad — по документации Apple; проверить на устройстве.
