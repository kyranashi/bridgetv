# Сайт BridgeTV и свой адрес

Сайт — это корневой `index.html` репозитория. Его публикует GitHub Pages (`.github/workflows/pages.yml`) вместе с веб-версией (`/web/`), программой передач (`/data/epg.json`) и каталогом фильмов (`/data/movies.json`). Код сайта лежит на GitHub, хостинг — тоже GitHub, оплаты нет.

Сейчас адрес — `https://kyranashi.github.io/bridgetv/`. Чтобы в адресе не было ни ника, ни «github», нужен свой домен. Хостинг остаётся на GitHub Pages.

Покупка домена — оплата, её делает владелец. Регистратору не нужны данные приложения; включите защиту данных владельца (WHOIS privacy) и двухэтапный вход в аккаунт регистратора.

## Как подключить (≈ 15 минут, один раз)

1. **DNS у регистратора** (для домена без www, напр. `bridgetv.app`) — четыре записи `A`:
   `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`,
   и запись `CNAME` для `www` → `kyranashi.github.io`.
   Для `bridgetv.js.org` DNS настраивают сами js.org по заявке.
2. **Подтвердить домен в GitHub** (защита от захвата домена): GitHub → Settings (аккаунта) → Pages → Add a domain → добавить TXT-запись, которую покажет GitHub.
3. **Переменная репозитория:** Settings → Secrets and variables → Actions → Variables → `SITE_DOMAIN` = `bridgetv.app`. Workflow `pages.yml` положит файл `CNAME` в сайт.
4. Settings → Pages → Custom domain → `bridgetv.app` → **Enforce HTTPS**.
5. В коде (делается одним коммитом):
   - `web/js/core.js` → `TV.PAGES = 'https://bridgetv.app'` (старый адрес оставить в `TV.PAGES_ORIGINS`);
   - `web/index.html` и `desktop/main.js` → в CSP `frame-src` добавить `https://bridgetv.app`;
   - README, `docs/*` — заменить ссылки.

Старый адрес `kyranashi.github.io/bridgetv` GitHub сам перенаправляет на новый, поэтому старые версии приложения продолжат работать.

## Безопасность сайта

- Статическая страница: нет сервера, базы, форм, cookies, входа — взламывать нечего.
- CSP `default-src 'none'`: только свои скрипты и картинки, без сторонних библиотек, шрифтов и счётчиков.
- Адреса скачивания собираются из зашитого списка файлов (`FILES`) — их нельзя подменить через адрес страницы.
- Защита от встраивания в чужой сайт (frame-busting) — GitHub Pages не даёт задать `X-Frame-Options`.
- HTTPS и HSTS — от GitHub Pages; `/.git`, `/.env`, исходники инструментов отдают 404 (проверено).
- Главные риски вне кода: взлом аккаунта GitHub или регистратора (→ двухэтапный вход) и сайты-двойники (→ один официальный адрес, контрольные суммы и подтверждение сборки на сайте).
