# Видео YouTube в BridgeTV (с 0.3.0)

## Почему поменялось

До 0.2.5 видео шло через публичные зеркала Invidious/Piped. В ноябре 2026 все известные публичные зеркала перестали отдавать видео (403, «HTTP 500», таймауты) — отсюда ошибки «YouTube недоступен: HTTP 500» и «Видео не открылось (таймаут)». Поддерживать работу через чужие зеркала больше нельзя, а обходить защиту YouTube от ботов проект не будет (это против правил YouTube и ненадёжно).

С 0.3.0 приложение **само выбирает источник по возможностям устройства** (Настройки → «Источник видео», по умолчанию «Авто»):

| Режим | Когда | Как работает |
|---|---|---|
| **Официальный плеер YouTube** | iOS 12+, Android 5+, ПК, Smart TV с новым браузером | встроенный плеер YouTube (IFrame API, домен youtube-nocookie.com), реклама и правила YouTube сохраняются |
| **Своё зеркало** | iPad на iOS 9–11, Android 4.4 — где официальный плеер не работает; или если выбрано вручную | ваш собственный сервер Invidious/Piped (адрес — в Настройках) |
| **Нет видео** | старое устройство без своего зеркала | вкладка подсказывает, что можно сделать |

С 1.1.0 вкладка «Видео» — только YouTube: «🔥 В тренде» первым (с ключом), свежие рубрики, мультфильмы и аниме. Фильмы и трейлеры — во вкладке «Фильмы» (каталог, docs/USER_GUIDE.md).

## Откуда берутся видео

1. **Подборки официальных каналов (без ключа).** RSS-ленты YouTube — открытый официальный формат. Подборки: «🆕 Новинки кино — трейлеры и премьеры» (Central Partnership, Кинопоиск, Netflix, Universal, Disney), «🧸 Новые мультфильмы» (Смешарики, Фиксики, Союзмультфильм, Pixar), «🌸 Аниме» (Muse Asia, Crunchyroll, Aniplex, GKIDS), «🎞 Классика» (Мосфильм, Беларусьфильм). Список — `TV.yt.feeds` в `web/js/services.js`. В браузере ленты недоступны (YouTube не разрешает их чтение со сторонних сайтов — CORS), в приложениях (iOS, Android, ПК) работают.
2. **Поиск, тренды, рубрики (с ключом).** YouTube Data API v3 — официальный API. Нужен **ваш бесплатный ключ** (ниже). Ответы кэшируются на 6 часов.
3. **Без ключа** поиск по видео открывает сайт YouTube в браузере.

## Как получить ключ YouTube API (5 минут, один раз)

1. На компьютере откройте <https://console.cloud.google.com> и войдите аккаунтом Google.
2. Создайте проект (любое название).
3. «API и сервисы» → «Библиотека» → **YouTube Data API v3** → «Включить».
4. «API и сервисы» → «Учётные данные» → «Создать учётные данные» → «Ключ API».
5. **Безопасность:** откройте ключ → «Ограничения API» → только «YouTube Data API v3». Так ключ нельзя использовать для других сервисов Google.
6. В BridgeTV: Ещё → Настройки → «Ключ YouTube API» → вставьте ключ.

Лимит бесплатный — 10 000 единиц в день: поиск стоит 100 единиц (≈100 поисков), подборки и тренды — 1 единица и кэшируются. Ключ хранится только на вашем устройстве и отправляется только на `www.googleapis.com`.

## Ошибки

| Сообщение | Причина | Что делать |
|---|---|---|
| «YouTube не разрешил показ во встроенном плеере…» (коды 101/150/152/153) | автор запретил встраивание, возрастное ограничение или YouTube попросил «подтвердить, что вы не бот» (часто при VPN и с адресов дата-центров) | открыть видео на сайте YouTube (кнопка в плеере); выключить VPN |
| «Видео удалено или недоступно» (100) | ролик удалён/приватный | — |
| «Нет связи» | нет интернета или YouTube заблокирован в сети | проверить сеть |

## Своё зеркало

Для старых устройств: разверните Invidious (<https://docs.invidious.io>) или Piped на своём сервере/ПК и укажите адрес в Настройках. Зеркало используется только с вашим адресом — встроенного списка публичных зеркал больше нет.

## Код

- `web/js/services.js` — `TV.yt.mode()`, `search`, `trending`, `channel` (RSS), `feeds`, `feed`, `embedUrl`.
- `web/yt.html` — страница официального плеера (IFrame API), сообщает приложению `ready/playing/paused/ended/error`. Размещается на GitHub Pages, потому что YouTube требует у встроенного плеера настоящий адрес сайта (Referer), а у страниц из файлов приложения его нет.
- `web/js/player.js` — `playEmbed()`, обработка сообщений плеера (проверка отправителя по origin).
- `web/js/core.js` — `TV.caps`: что умеет устройство (H.264, HEVC, VP9, AV1, HLS, максимальное качество).
