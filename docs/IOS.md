# iOS: сборка, установка, ограничения

## Целевое устройство

| | |
|---|---|
| Проверочное устройство | iPad mini 1 (A1455, A5, armv7, 512 МБ ОЗУ), iOS 9.3.x |
| Минимальная iOS | 9.0 (нужен `WKWebView.loadFileURL`) |
| Архитектуры | armv7 + arm64 (один «толстый» бинарник) |
| Bundle ID | `com.kyranashi.tv` (тот же, что у v1.0 — обновление ставится поверх) |
| Установка | с джейлбрейком (AppSync Unified) — как есть; **без джейлбрейка** — переподписать своим Apple ID (Sideloadly, AltStore, TrollStore), см. ниже |
| Новые устройства | iPhone/iPad на iOS 11–18: arm64, экраны запуска под все размеры, ключ `UILaunchScreen`, пометка SDK 14 — приложение на весь экран |

## Установка на iPad

1. Получите `BridgeTV.ipa`:
   - GitHub → Actions → «Сборка iOS (BridgeTV.ipa)» → последний запуск → артефакт **BridgeTV-ipa** (zip с `BridgeTV.ipa`), или
   - GitHub → Releases (для версий с тегом `v*`), или
   - соберите сами (ниже).
2. Джейлбрейк активен (для iOS 9 — Carbon/Phoenix → Run).
3. 3uTools → **Приложения** → **Импорт** → `BridgeTV.ipa`. Обновление — так же, поверх; избранное и настройки сохраняются (они в данных WKWebView).
4. Первый запуск: **Ещё → Помощь и сертификаты → «Установить сертификаты»**. Откроется Safari → «Установить» → Настройки → Основные → Профили → «BridgeTV: сертификаты для старых iOS» → Установить. Нужно один раз.

### Зачем сертификаты

С 2021 года почти весь интернет перешёл на корневые сертификаты Let's Encrypt (ISRG Root X1, а с 2025 — поколение Y: ISRG Root YR/YE). iOS 9–10 их не знают, поэтому:
- зеркала YouTube, GitHub (обновление каталога) и многие трансляции «вечно грузятся» или не открываются;
- то же в Safari.

Приложение для своих запросов (поиск, YouTube API, каталог) уже доверяет этим корням само (`TVTrust` в `main.m`), а **видео** проигрывает система — ей нужен установленный профиль. Профиль содержит только 4 официальных корневых сертификата с https://letsencrypt.org/certificates/ и удаляется в Настройки → Основные → Профили.

Без приложения (только Safari) профиль ставится с ПК: запустите `python tools/serve.py` и откройте на iPad в Safari `http://<IP-ПК>:8080/web/certs/BridgeTV-roots.mobileconfig`.

## Без джейлбрейка (любой iPhone/iPad)

**Почему раньше «без джейлбрейка не открывалось».** iOS запускает только приложения, подписанные сертификатом Apple. Наш `.ipa` подписан «пустой» подписью (`ldid -S`, fakesign) — её принимает только джейлбрейк с AppSync. Обойти это нельзя ни в каком приложении: подпись должна сделать Apple ID владельца устройства. Один и тот же `.ipa` подходит для всех способов — инструменты переподписывают его сами.

| Способ | Какие iOS | Как часто переподписывать | Что нужно |
|---|---|---|---|
| **Sideloadly** (Windows/macOS) | iOS 7 – 18, в т.ч. **iPad mini 1 на iOS 9** | каждые 7 дней (бесплатный Apple ID) | ПК, кабель, iTunes и iCloud с сайта Apple (не из Microsoft Store), любой Apple ID |
| **AltStore / SideStore** | iOS 12.2+ | 7 дней, продлевается само по Wi‑Fi | ПК с AltServer (для первой установки) |
| **TrollStore** | iOS 14.0 – 16.6.1 и 17.0 | **навсегда**, без Apple ID | поддерживаемая версия iOS |
| **Платный аккаунт разработчика Apple** ($99/год) | любые | раз в год | Xcode или Sideloadly с этим аккаунтом |
| **Веб-версия** без установки | любые (Safari) | — | Safari → «Поделиться» → «На экран Домой» (см. [WEB.md](WEB.md)) |

**Sideloadly пошагово (Windows):**
1. Установите iTunes и iCloud **с сайта apple.com** (версии из Microsoft Store не подходят), затем Sideloadly с https://sideloadly.io.
2. Подключите iPad кабелем, нажмите на iPad «Доверять этому компьютеру».
3. В Sideloadly: перетащите `BridgeTV-<версия>.ipa`, введите Apple ID → Start. Пароль вводится только в Sideloadly (лучше завести отдельный Apple ID).
4. На iPad: Настройки → Основные → Профили и управление устройством → ваш Apple ID → «Доверять».
5. Через 7 дней приложение перестанет открываться — повторите шаг 3 (данные сохранятся).

Бесплатный Apple ID может поменять Bundle ID — тогда это будет отдельное приложение рядом с джейлбрейк-версией.

**На новых устройствах.** Бинарник «толстый» (armv7 для старых iPad и arm64 для всех новых). Чтобы новые iPhone/iPad не показывали приложение в «рамке совместимости», в 0.2.5 добавлены:
- экраны запуска `Default-*` для iPhone X…16 и iPad Pro/Air/mini (делает `tools/make_launch_images.py`);
- ключ `UILaunchScreen` в Info.plist (iOS 14+);
- пометка SDK 14.0 в заголовке бинарника (`tools/set_sdk_version.py`, минимальная версия остаётся 9.0).

## Сборка `.ipa`

### Вариант 1. GitHub Actions (ничего ставить не нужно)
Любой push в `main`, затрагивающий `ios/`, `web/` или `data/catalog.js`, запускает `.github/workflows/ios.yml` (Ubuntu): ставит тулчейн, вызывает `ios/build.sh`, выкладывает артефакт. Тег `v2.0.0` → релиз с `BridgeTV.ipa`.

### Вариант 2. Linux / WSL
```bash
bash tools/setup_toolchain.sh      # один раз: clang + ld64 + ldid + iPhoneOS10.3.sdk в ~/iosbuild
python3 tools/build_catalog.py     # если нужно обновить каналы (2–5 мин)
bash ios/build.sh                  # -> ios/build/BridgeTV.ipa
```
Переменные: `IOS_TC` (папка с clang/ld/ldid/lipo), `IOS_SDK`, `ARCHS` (по умолчанию `"armv7 arm64"`; для быстрой сборки только под iPad mini 1 — `ARCHS=armv7`).

Что делает `build.sh`:
1. компилирует `src/main.m` под каждую архитектуру (`-target <arch>-apple-ios9.0`, ARC, без исключений) и склеивает `lipo`;
2. копирует `res/*` (Info.plist, иконки, экраны запуска);
3. копирует интерфейс в `BridgeTV.app/www/web` (без `vendor/` — на iOS HLS играет система) и каталог в `BridgeTV.app/www/data/catalog.js`;
4. подписывает `ldid -S`, упаковывает `Payload/` в `BridgeTV.ipa`.

### Проверка после сборки
`build.sh` в конце сам запускает `python3 tools/check_ipa.py build/BridgeTV.ipa` (работает и на Windows, без otool/nm): для каждой архитектуры проверяет минимальную версию 9.0 и отсутствие символов iOS 10+. Если они есть — сборка падает (так CI не выпустит `.ipa`, который не запустится на iPad).

**Урок 09.11.2026.** Первая сборка 0.2.0 содержала `_objc_alloc` (iOS 12+) и `_objc_unsafeClaimAutoreleasedReturnValue` (iOS 10+) — clang 11 вставляет их сам. Решение:
- флаги `-fobjc-runtime=ios-9.0 -fno-objc-convert-messages-to-runtime-calls` — убирают `objc_alloc`;
- `objc_unsafeClaimAutoreleasedReturnValue` clang всё равно вставляет, когда результат метода отбрасывается (`loadFileURL`, `reload`), поэтому в `main.m` есть своя реализация этой функции (возвращает указатель как есть — объект уже в autorelease-пуле).

## Правила кода под iOS 9 / armv7 (обязательно)

Стабы SDK из theos и старый рантайм накладывают ограничения:
- **нельзя** пустые литералы `@[]` и `@{}` — символы `___NSArray0__`/`___NSDictionary0__` появились в iOS 10, приложение не запустится на iOS 9. Используйте `[NSArray array]`, `[NSDictionary dictionary]`; непустые литералы допустимы, но в коде используется `arrayWithObjects:`;
- **нельзя** `@try/@catch` (сборка с `-fno-objc-exceptions`);
- **нельзя** оператор `%` для знаковых целых на armv7 (нет `___modsi3` в стабах) — используйте беззнаковые или деление;
- **нельзя** приводить `double` к 64-битному целому (`(long long)`, `(unsigned long long)`) на armv7 — нужен `___fixunsdfdi`/`___fixdfdi`, которых нет в стабах (поймано в 0.2.4: имя файла загрузки). Для строк используйте формат `%.0f`;
- **нельзя** API новее iOS 9.0 (`if (@available)` тоже нельзя — нет символа). Устаревшие, но рабочие на 9 API (`requiresUserActionForMediaPlayback`) — допустимы;
- `UIRequiredDeviceCapabilities = armv7`, `MinimumOSVersion = 9.0`, `NSAllowsArbitraryLoads = true` (многие трансляции по http).

## Отладка на устройстве

- Логи: 3uTools → «Инструменты» → «Журнал реального времени», фильтр `BridgeTV`.
- Интерфейс можно отлаживать на ПК: `python tools/serve.py` → `http://localhost:8080/web/` (в браузере `TV.native === false`, запросы идут обычным XHR).
- Если WebKit выгрузился из-за нехватки памяти, `TVWebVC` перезагружает страницу сам (`webViewWebContentProcessDidTerminate`).

## Ограничения iPad mini 1 (A5)

- H.264 до 720p стабильно, 1080p — через раз, HEVC/AV1/VP9 — нет (проверка каталога отбрасывает HEVC-only каналы).
- 512 МБ ОЗУ: включён лёгкий режим (меньше картинок, логотипы через ресайзер, списки порциями по 48).
- Картинка-в-картинке не поддерживается железом.
