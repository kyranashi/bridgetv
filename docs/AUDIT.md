# Предварительный аудит: право и безопасность (0.3.0)

> **Это не юридическое заключение и не гарантия соответствия.** Это предварительный разбор от 11.11.2026, который помогает подготовиться к консультации с юристом и к независимой проверке безопасности. Нормы меняются; всё, что отмечено ⚖️, нужно подтвердить у юриста в конкретной стране.

> Метки: **[закон]** — обязательно по закону · **[магазин]** — требование магазина/платформы · **[практика]** — рекомендуемая практика (best practice).

## 3. Чек-лист безопасности

### OWASP MASVS v2

| Группа | Статус |
|---|---|
| STORAGE — чувствительные данные | ✅ паролей нет; ключ YouTube хранится в хранилище приложения (не в общей памяти), поле ввода — `password` |
| CRYPTO | ✅ своей криптографии нет; только TLS системы |
| AUTH | — аккаунтов нет |
| NETWORK | ✅ TLS; ⚠️ IPTV-потоки часто по http (это природа источников, данные — публичное видео); старым устройствам добавлены корни Let's Encrypt, а не отключена проверка |
| PLATFORM — WebView и мосты | ✅ белый список команд, только http/https, лимиты, CSP; ⚠️ остаточные риски ниже |
| CODE — зависимости | ✅ Dependabot, CodeQL, закреплённые действия CI |
| RESILIENCE — подлинность сборок | ✅ сборка только в CI, attestation, SHA256SUMS; ⚠️ нет подписи кода Windows/Apple |
| PRIVACY | ✅ нет аналитики и трекеров |

### OWASP API Top 10 (2023)
Своего API нет. Применимо только **API2/API8 (ключи и конфигурация)**: ключ YouTube — у пользователя, рекомендовано ограничить его только YouTube Data API v3 (инструкция в приложении). Утечка ключа → расход чужой квоты, не доступ к аккаунту.

### WebView / мосты — остаточные риски

| Риск | Где | Почему оставлено | Смягчение |
|---|---|---|---|
| `setAllowUniversalAccessFromFileURLs(true)` | Android | без него не открываются потоки без CORS из `file://` | CSP запрещает чужие скрипты; каталог проверяется; переходы на чужие страницы запрещены |
| мост `TVAndroid` виден и во встроенных фреймах (плеер YouTube) | Android 4.4+ | `addJavascriptInterface` не различает фреймы; `WebMessageListener` нет на старых Android | команды ограничены (только http/https, своё хранилище); фреймы — только YouTube и свой GitHub Pages |
| мост iOS | iOS | — | принимаются только сообщения главного фрейма |
| ослабление CORS | ПК | чтобы IPTV-потоки открывались | только для запросов главной страницы приложения |

### Сторонние SDK и ИИ
- SDK аналитики/рекламы: **нет**. hls.js — проверенная библиотека с открытым кодом.
- ИИ в приложении не используется → требования EU AI Act и т. п. не применяются.

## 5. Дорожная карта (3 этапа)

1. **Сейчас (некоммерческий открытый проект)** — сделано в 0.3.0: политика конфиденциальности, официальный YouTube, безопасность мостов и CI, проверка сборок. Осталось: ежеквартальный пересмотр безопасного режима.
2. **Перед ростом аудитории (> 10 000)** — консультация юриста по ИС (РБ/РФ), договорённости с вещателями главных каналов или переход на их официальные потоки, сертификат подписи кода Windows, независимый тест на проникновение мостов (MASVS L1).
3. **Перед магазинами или коммерцией** — юрлицо, договоры/лицензии на контент, отказ от неофициальных потоков, возрастная маркировка, полная проверка MASVS L2, DPIA по GDPR при сборе любых данных.

## 8. Нормы для проверки у юриста ⚖️

1. РФ 149‑ФЗ: ст. 10.5 (аудиовизуальные сервисы), 15.2 и 15.6‑1 (блокировки), 15.8 (VPN).
2. РФ ГК ст. 1270, 1281 (исключительное право, сроки), практика по гиперссылкам.
3. РФ 436‑ФЗ (возрастная маркировка) — применимость к приложению-агрегатору ссылок.
4. РФ КоАП 13.53, 20.33; УК 284.1 — риски пользователей при доступе к материалам из реестров.
5. РБ: Закон № 99‑З (персональные данные), Закон «О СМИ», Закон «Об авторском праве и смежных правах», КоАП 19.11, УК 361‑1.
6. ЕС: GDPR ст. 3(2), 13; ePrivacy (cookies YouTube-плеера); дело CJEU *Fashion ID* (C‑40/17) — совместная ответственность за встроенные сторонние плагины.
7. США: DMCA §512 (порядок уведомлений), исключение §1201 для джейлбрейка.
8. Условия API-сервисов YouTube и Политика разработчика YouTube — для режима с ключом пользователя.
